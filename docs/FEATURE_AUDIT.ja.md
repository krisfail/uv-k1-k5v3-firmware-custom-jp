# K1／K5 V3版の機能採否と監査

PY32F071搭載のUV-K1／UV-K5 V3向け`wrx-jp`で有効・保留・除外となる機能を示します．

## 判断基準

機能は，受信機としての価値，安全性，LCD上での分かりやすさ，保存形式への影響，実機での確認しやすさの順に評価します．K1／K5 V3はK5よりフラッシュに余裕がありますが，送信経路，送信校正，送信を前提とする保守機能は有効にしません．

## 優先順位

| 優先度 | 対象 | 判断 |
| --- | --- | --- |
| A | 受信経路，受信設定，固定UIと外部チャンネル名，受信専用の安全境界 | 互換性とLCD上の意味を確認しながら維持する |
| B | 追加字形，受信履歴，小型の補助表示，上流の非送信UI改善 | RAM，表示幅，操作性，実機確認の見通しが立つ範囲で追加する |
| C | 大型の解析画面，送信系・保守系の機能 | 受信専用版では採用しない。受信経路とUIの品質を優先する |

## 残す機能

| 分類 | 機能 | 採用理由・境界 |
| --- | --- | --- |
| 安全 | RX-only，PTTモニター，TX要求時の`RX ONLY`表示 | RF送信を無効にし，PTTを受信モニターに固定する（内部状態名は`TX DISABLE`） |
| 受信 | AM/FM，受信帯域の選択 | 受信操作に必要 |
| 受信 | 日本向けFM放送，周波数ステップ，RXExt，逆CTCSS | 国内の受信操作と選択性を改善する |
| 走査 | バンドプリセット，範囲スキャン，スキャン一時スキップ，RSSI／進捗表示 | 受信専用機としての探索性を高める |
| 音声 | 受信音声プロファイル，音声スコープ，音声レベル表示，FM AGCガード，AM補正 | K1の余裕を使い，受信状態の確認と聴きやすさを優先する |
| UI | ASCII固定UI，外部フォントによるチャンネル名，カテゴリ表示，サイドキー操作選択，起動画面，MESSAGE／ALL，簡易ヘルプ，画像／メッセージ表示，フォントatlas | 固定UIはフォント未書込みでも読める表記を優先し，日本語は外部16×16／8×8縮小／ASCII別名を選べるチャンネル名に限定する．カテゴリと操作選択は送信系候補を除外する |
| 状態 | スリープ，復帰状態，LCD反転・コントラスト，狭帯域化，チャンネル名・バンク | 受信運用に直接使える範囲で維持する |
| 接続 | 専用host tool，CHIRP互換アダプタ，UART（低レベル校正操作を除く） | 通常のメモリー管理に必要．calibration領域は通常経路から除外 |

## 追加検討する機能

| 機能 | 採用条件 |
| --- | --- |
| 追加漢字・大字形 | ライセンス確認，atlasの重複確認，LCD幅と基線の実機確認 |
| 受信履歴やスキャン詳細 | RAM，操作性，電池消費，保存形式を確認できること |
| 小型の受信補助表示 | メイン受信画面を圧迫せず，無効化設定と実機試験を追加できること |

フラッシュに余裕があっても，大型の送信系・解析系・保守系機能は有効にしません．受信経路とUIの品質を優先します．

## 上流由来の非送信機能

上流更新で追加された機能のうち，受信運用とUIに直接役立つものは`JpRxOnly`で有効にしています．FM放送スキャン中に通常チャンネルの受信処理が割り込まない制御，メモリースキャンのチャンネル名表示中に再開タイマーを保留する制御，Dondji風カテゴリランチャーの`ALL`フォールバック，カテゴリ項目数の2桁表示，`F`＋サイドキー長押しの操作選択が対象です．上流変更とRX-only境界の対応表は[上流からの受信向け取り込み](UPSTREAM_INTEGRATION.ja.md)にまとめています．

アクション選択は受信操作（モニター，スキャン，FM，VFO切替，帯域幅など）だけを候補にし，RX専用版では`POWER`と`PTT`を表示しません．古い保存設定に送信系アクション番号が残っていても，実行側で拒否します．Fox Hunt／Beacon，BYP／BYP+，送信タイマー，送信電力・送信トーンを伴う機能は，RX専用版では無効です．

## RX専用版から外した機能

次の機能はCMakeのRX-only強制境界で無効化し，通常プロファイルのメニューにも出しません．ソースに残る機能も，ビルド対象とメニューからは除外します．

- RF送信，送信電力・送信帯域の変更，AM時送信，1750 Hz送信，VOX，TOT，アラーム，DTMF calling
- AirCopy，REGA，F_CAL，F Lock，電池校正メニュー，UARTからのBKレジスタ書き換え
- NOAA／voice，full spectrum，game，K5 viewer，charging，rescue操作，音量拡張
- PMR，GMRS／FRS／MURS，デバッグ，メモリー診断，QRコード，受信／送信タイマー

専用host tool，CHIRP互換アダプタ，UART通信そのものは残しますが，低レベル保守コマンドまでRX-onlyの安全境界を保証するものではありません．正規host toolの操作分離は[機能の技術詳細](FEATURES_TECHNICAL.ja.md)に記載します．

## 確認項目

1. `CMakeLists.txt`と`CMakePresets.json`の強制無効化境界，メニューの条件コンパイル，PTT分岐を確認する．
2. `cmake --build --preset JpRxOnly -j2`とホストテストを実行する．
3. `cmake --build --preset JpRxOnly -j2`の最後に出るFLASH／RAMの使用量を記録する．
4. [HARDWARE_TEST_PLAN.ja.md](HARDWARE_TEST_PLAN.ja.md)へ実機結果を記入する．
5. フォントを変更した場合は，[BITMAP_ATLAS.ja.md](BITMAP_ATLAS.ja.md)と実機表示を確認する．

## LCDエミュレーターによるUI監査

`tools/lcd_emulator.py`で固定UI，受信画面，警告画面を128×64ドットへ描画し，文字の重なり，右端の欠け，カテゴリ件数，左右キーの誘導を確認する．これは静的な配置監査であり，実機のコントラスト，応答時間，外部Flashからのフォント読出しを保証しない．

現行受信画面の修正前の静的評価は4／10だった．`ENABLE_BIG_FREQ`，`ENABLE_RSSI_BAR`，`ENABLE_FEAT_F4HWN`を有効にした`MDF_NAME_FREQ`の描画では，ファームウェア自身の描画領域が衝突していた．エミュレーターで単一VFO・デュアルVFO・16×16チャンネル名・ASCIIフォールバック・8×8名を比較し，修正後はページ衝突と名前位置の不一致が解消したことを確認する．

表示モードごとの結果は次のとおりである．デュアルVFOは設定値にかかわらず，4ページの表示領域へ収めるため名称と周波数を小字形へ揃える．単一VFOのASCII表示は外部字形を使わず，収まる限り大字形で表示する．

| 表示状態 | 修正後の結果 | 重大度 |
| --- | --- | ---: |
| 単一VFO・16×16名称＋周波数 | 補助情報をページ4へ移し，周波数との衝突を解消 | 0 |
| デュアルVFO・16×16設定＋周波数 | デュアルVFOでは名称を8×8へ切り替え，周波数を小字形にしてRSSIとの衝突を解消 | 0 |
| 単一VFO・8×8名称＋周波数 | 補助情報をページ4へ移し，大字形周波数との衝突を解消 | 0 |
| デュアルVFO・8×8名称＋周波数 | 周波数を小字形にし，補助情報とRSSIを専用ページへ分離 | 0 |

| 重要度 | 指摘 | 対応・残課題 |
| --- | --- | --- |
| 重大 | `NAME+FREQ`の周波数と補助情報が同じページを使用していた | 単一VFOは補助情報をページ4へ移し，デュアルVFOは名称8×8＋小字形周波数へ切り替えた |
| 重大 | デュアルVFOではRSSI表示がページ3を消去し，第1 VFOの大字形周波数を破壊していた | デュアルVFOの周波数をページ1／5の小字形へ置き，RSSIページを専用化した |
| 中 | 16×16名称，大字形周波数，6×8チャンネル番号，3×5補助情報の階層が揃っていなかった | 単一VFOは主情報を大きく保ち，デュアルVFOは名称と周波数を同じ小型階層へ揃えた。補助情報は6×8の一行へまとめた |
| 中 | 外部16×16名称とASCIIフォールバックで位置基準が異なっていた | 同じ名前欄を使って中央寄せするよう統一した |
| 高 | 実機LCDでの視認性と外部フォント転送後の表示は未確認 | [実機試験票](HARDWARE_TEST_PLAN.ja.md)の受信画面，警告，8×8，16×16，ASCIIフォールバックを実機で確認する |

静的監査上は9／10まで改善した．10／10にするには，実機でコントラスト，基線，外部Flash読出し，単一／デュアルVFOの表示切替を確認し，ASCIIフォールバックとIzumi字形の見た目を実機で最終確認する必要がある．
