# 上流v5.9.0からの受信向け取り込み

この文書は，K1／K5 V3版で上流v5.9.0系列から取り込んだ機能と，`JpRxOnly`で加えた受信専用境界を記録する．K1とK5 V3は同じPY32F071系のコードベースを使用する．旧UV-K5版は別の上流世代を基にしているため，取り込み範囲を混同しない．

## 対象版と範囲

このフォークのv5.9.0統合は，armel側のv5更新を取り込んだ`435192e3`（PR #511のマージ）を基準とする．`9c86a7c3`はv5.9.0の版準備であり，実行時の機能追加ではない．ここでは受信運用またはUIに直接関係する変更だけを説明し，送信系の機能や上流から変更なく存在するコードは対象外とする．

### メニューカテゴリとALL

カテゴリは表示用のビューであり，通常メニューのID，項目順，設定値の意味を別の番号へ変換しない．コンパイル条件によって実在しない項目はカテゴリから除き，表示可能な項目がないカテゴリは一覧に出さない．`ALL`はカテゴリ固有の配列を使わず，現在のビルドで有効な通常メニュー全体を表示する．

カテゴリ名は`App/ui/menu_text.h`で管理する．これは日本語文言の正本であり，カテゴリ機能そのものの判定や保存形式を持たせない．

### サイドキー操作選択

`F`を押した状態でサイドキーを長押しすると，候補の前後をメイン画面で確認できる．`UP`／`DOWN`で候補を移動し，`M`のリリースで現在の候補を実行する．この操作は既存のアクションテーブルを呼び出す一時選択であり，サイドキー設定のEEPROM形式を変更しない．

候補表から`POWER`と`PTT`を除外し，実行側でも送信系アクションを拒否する二重境界を設けている．古い設定値や予期しないアクション番号が実行側へ到達した場合も，無線送信へ進まず拒否音を返す．

### FMスキャンと通常受信の競合

FM放送スキャン中は，通常チャンネル側の着信確認と着信処理の両方でFMスキャン状態を確認する．これにより，通常チャンネルのスケルチ開放がFMスキャンを途中で奪う経路を塞ぐ．通常のFM放送受信（スキャン停止中）ではこの抑止を行わない．

### メモリースキャンの再開保留

メモリーチャンネル名を表示している間は，表示用カウントが残っている場合に限り次の走査再開を保留する．チャンネル名を表示しない周波数走査へ同じ遅延を適用しないため，走査速度を不必要に落とさない．

## 受信専用版での境界

上流機能を有効にしても，次の境界は解除しない．

- RF送信経路，送信系メニュー，送信を誘発するサイドキー候補をビルド対象から外す．
- PTTはモニター操作として扱い，予期しないTX要求は最終ゲートで拒否する．
- `POWER`，`PTT`，送信電力・送信トーン・送信タイマーに関係するアクションは，候補表示と実行の双方で拒否する．
- `RXExt`は追加受信機能のスイッチであり，受信専用，日本語表示，PTTモニター，国内FM放送帯域の制約を解除しない．

## 検証範囲

ホストテストでは，カテゴリの空項目除外と`ALL`表示，2桁表示，サイドキー操作選択のRX-only除外，FMスキャン中の受信抑止，メモリースキャン再開保留のソース境界を確認する．ビルドは`JpRxOnly`で行う．これらはソースとビルドの検証であり，LCDの視認性，FM放送の選択度，実機での走査タイミング，RF送信が発生しないことを単独で保証しない．実機確認は[実機テスト計画](HARDWARE_TEST_PLAN.ja.md)に従う．
