# K1版 日本語表示・受信機能の優先度

K1／K5 V3はK5よりフラッシュに余裕がありますが，LCDの表示幅と既存の1 byteフォント形式は共通の制約です．機能は，受信専用としての安全性を維持しつつ，表示の分かりやすさを優先して追加します．

この文書は開発者向けの計画・容量判断資料です．利用者向けの機能説明は[README.ja.md](../README.ja.md)を参照してください．

> 採用・保留・除外の現行判断は[FEATURE_AUDIT.ja.md](FEATURE_AUDIT.ja.md)にまとめています．この文書では，表示品質，容量，受信機としての有用性に基づく優先順位を示します．実機試験には[HARDWARE_TEST_PLAN.ja.md](HARDWARE_TEST_PLAN.ja.md)を使います．

## 優先度

| 優先度 | 対象 | 方針 |
| --- | --- | --- |
| A | 帯域幅，FM放送，バンドプリセット，スキャン，RXExt | 受信経路と保存形式の互換性を確認しながら維持する |
| A | メニュー名，状態表示，起動画面，ヘルプ | 既存フォントを優先し，短い日本語で意味を明確にする |
| A | 送信系ビルド経路 | CMake入口で強制無効化し，送信系モジュールを登録しない |
| B | 追加漢字，設定値の日本語化 | atlasで重複と空きコードを確認し，LCD幅を実機で確認する |
| B | 受信状態の説明表示 | TX DISABLEなど安全上必要な英字は残し，誤解を招かない範囲で日本語化する |
| B | 上流の非送信UI・走査改善 | 受信割り込み抑制，走査名表示の再開保留，カテゴリ，操作選択，2桁表示を優先して取り込む |
| C | 大型の新規解析画面 | フラッシュに余裕があっても，走査時間・RAM・視認性を確認してから採用する |

## 現時点の整理

- 帯域幅，表示，電池校正を既存の字形でメニューへ追加しました．
- 送信出力の`LOW`／`HIGH`表示は受信専用画面から外しました．電池低下・過電圧の安全状態表示は残します．
- TX DISABLEは安全状態を明確にするため，英字表記を維持しました．
- 送信可能な上流系CMakeプリセットを削除し，ビルド入口をJpRxOnlyにまとめました．
- 上流v5.9.0から，送信経路を持たないFMスキャン保護，走査表示保留，メニューカテゴリ，サイドキー操作選択，2桁表示を取り込みました．送信系候補は一覧と実行側の両方でRX-only境界を維持します．

新しい字形を追加する場合は，フォント注釈，フォント一覧，atlas編集手順を更新します．文字コードの再利用や校正領域の利用は行いません．
