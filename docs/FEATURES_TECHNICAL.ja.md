# wrx-jp 新機能技術詳細（UV-K1 / UV-K5 V3）

この文書は、PY32F071搭載のUV-K1／UV-K5 V3向け`JpRxOnly`（`wrx-jp`）について、実装者・レビュー担当者がコードとデータ境界を確認するための技術資料です。利用者が最初に読む文書ではありません。対象、書き込み前の注意、通常の操作は[README.ja.md](../README.ja.md)、日常操作は[CHEATSHEET.ja.md](../CHEATSHEET.ja.md)を先に参照してください。

## 1. 正規の実装入口と前提

正規ビルドは`CMakePresets.json`の`JpRxOnly`です。主な定義は次のとおりです。

| 定義 | 役割 |
| --- | --- |
| `ENABLE_RX_ONLY` | 送信経路・送信系UIを無効化し、PTTをモニター操作にする |
| `ENABLE_JAPANESE` | 日本語メニューと拡張フォントを有効化する |
| `ENABLE_RX_AGC_GUARD` | 通常のFM受信時の急激なAGC変化を抑える |
| `ENABLE_FMRADIO` | FM放送機能を有効化する |
| `TARGET=wrx-jp` | 生成物を上流版と区別する |
| `EDITION_STRING=JP-RX-Only` | 無線機上の版の用途を明示する |

K1とK5 V3は同じPY32プロファイルとして実装しています。旧UV-K5（DP32G030）のEEPROMマップやドライバ仕様を、この文書のアドレスへ読み替えてはいけません。

`RXExt`は追加した受信機能のマスター設定です。OFFで停止する対象はプリセット、SINGLE受信、メモリーバンク絞り込み、自動スケルチ、AGCガード、一時スキップです。受信専用制約、PTTモニター、日本語表示、3段階の通常受信帯域幅、FM放送の76.0–95.0 MHz制限は`RXExt`では解除されません。

## 2. 受信専用ポリシー

- `ACTION_Ptt()`は送信処理へ進まず、PTTはモニター操作として扱います。
- 送信系のメニュー、VOX、DTMF calling、送信トーンなどは`JpRxOnly`の定義でビルド対象から外しています。
- DUAL WATCHやCROSS BANDなど、送信経路を伴う状態から追加受信機能を起動しないよう、プリセット側にも拒否条件があります。
- この版は国内向け受信機として提供するもので、送信可能版の作成・再有効化はこの機能仕様の対象外です。

## 3. 追加受信機能

### 3.1 受信モード

受信モードは`MAIN ONLY`、`DUAL RX`、`SINGLE`です。`SINGLE`は`RXExt`の有効時だけ選択でき、VFO切替を抑制します。状態はグローバル設定に保存されます。

### 3.2 通常受信の帯域幅

K1／K5 V3では、実効差のないW+をメニューから外し、次の3段階にします。

| 表示 | 目標帯域幅 | 内部モード |
| --- | ---: | --- |
| `W` | 20 kHz | `BANDWIDTH_WIDE` |
| `N` | 12.5 kHz | `BANDWIDTH_NARROW` |
| `N-` | 6.25 kHz | `BANDWIDTH_NARROWER` |

`ACTION_Wn()`は`W → N → N- → W`の順に切り替えます。周波数ステップは帯域幅とは独立しており、既存のステップ選択から6.25／12.5／20／25 kHzを個別に選べます。これにより、FM放送など別の刻みを使うプリセットを壊しません。

K1／K5 V3のBK4829では、REG43の`<5:4>=10`が25 kHz／20 kHzを共通のハードウェアモードとして定義しています。Wは`BK4819_REG_43=0x3028`、Nは`0x4048`、N-は`0x2058`です。W+を別表示・別状態として残してもRF設定が変わらないため、このプロファイルでは実装しません。

帯域幅モードは、RX-only構成で標準チャンネル記録のbyte 7へ`0x80 | mode`として保存します。既存のbyte 4（WIDE/NARROW一ビット）は互換用に保持し、markerがない旧チャンネルや旧WIDE+状態はWへ正規化します。校正領域や外部フラッシュのバンク領域は使いません。

### 3.3 自動スケルチ

自動スケルチは受信開始時などにRSSI、noise、glitchを8回、2 ms間隔でサンプリングします。平均値から次の6閾値を作り、通常の`BK4819_SetupSquelch()`へ渡します。

```text
open RSSI   = RSSI + 8       close RSSI   = RSSI + 4
open noise  = max(noise - 8, 0)
close noise = max(noise - 4, 0)
close glitch = glitch + 4     open glitch  = glitch + 8
```

各値は8 bit範囲へクランプします。自動スケルチの要求は一度消費すると再利用されず、`RXExt`または自動スケルチがOFFなら適用しません。

### 3.4 AGCガード

`ENABLE_RX_AGC_GUARD`時、`RXExt`有効、通常のFM受信、スキャン停止中、FM放送モード外だけで動作します。周波数ごとに前回サンプルを保持し、RSSI差が12以上または受信ゲイン差が8以上になった場合にAGCを一時停止します。停止保持はスケジューラ30回で、満了時にAGCを再有効化します。AMやFM放送の設定をこの処理が上書きしないよう、他の無線再構成経路を優先します。

### 3.5 メモリーバンク

チャンネルにはバンク番号0～8を持たせます。選択バンクが0（ALL）のときは全チャンネル、1～8のときは一致するチャンネルだけをメモリースキャン候補にします。保存形式は標準の周波数・名前・校正データと分離しています。

### 3.6 一時スキップ

スキャン中の一時スキップは周波数をRAM上の最大16件のリストへ追加します。同一周波数は重複登録せず、満杯の場合は追加しません。周波数スキャンとメモリースキャンの両方で候補を確認し、候補をすべて飛ばした場合も無限ループにならないよう試行回数に上限を設けています。電源再投入やスキャン範囲のリセットで消えます。

### 3.7 受信バンドプリセット

周波数表示中に`STAR`で一覧を開き、`UP/DOWN`で選択、`M`で適用、`STAR`で適用後にスキャン開始、`EXIT`でキャンセルします。周波数モード、スキャン停止、デュアル受信・クロスバンド無効などの条件を満たさない場合は適用しません。適用時は候補周波数を一つずつ`RX_freq_check()`で検証します。

### 3.8 FM放送と日本向け仕様の照合

日本のFM放送局周波数の目安は76.1–94.9 MHzです。総務省系NICTの資料でも、臨時災害放送局用FM機器の送信可能周波数を76.1–94.9 MHz、電波型式をF3E/F8E（モノラル／ステレオ）として示しています（[NICT公式資料](https://www2.nict.go.jp/resil/book/2024/46132-book/pageindices/index87.html)）。

現行実装は次の構成です。

| 項目 | 現行実装 | 判定 |
| --- | --- | --- |
| RFハードウェア | BK1080の76–108 MHzモード | 日本向け範囲を包含するため妥当 |
| UI・設定・CHIRP範囲 | 76.0–95.0 MHz、0.1 MHz単位 | 局範囲の外側に100 kHzずつ余裕がある |
| 周波数刻み | 内部単位で1、すなわち100 kHz。`FM_Space`の選択肢は無効化 | 日本の100 kHz級の局間隔に適合 |
| ステレオ／FM復調 | BK1080のFM放送モードへ委譲 | ソース上でモノラル／ステレオを個別選択する機能はない |

結論として、76.1–94.9 MHzの日本の局を受信する用途には概ね対応しています。ただし、現在は76.0 MHzと95.0 MHzも入力・スキャン端点として許可するため、仕様範囲と厳密に一致していません。これは受信機のガード範囲としては有害ではありませんが、厳密に合わせるならUI・自動選局・CHIRPの検証範囲を761–949（0.1 MHz単位）へ変更し、BK1080の内部ハードウェア範囲だけを760–950のまま保持する設計が候補です。この作業では互換性を優先してコード変更は行っていません。

### 3.9 スキャン候補の受信確認と表示

周波数スキャンがVHF帯の第2高調波に相当する候補を検出した場合、候補周波数だけで判定を確定しません。候補の半分の周波数へ一度同調してRSSIを読み、その後候補周波数へ戻して再度RSSIを読みます。基礎周波数側が十分強い場合は、CSSスキャンへ渡す周波数を基礎周波数へ置き換えます。これにより、VHF帯で高調波を実信号として扱う誤停止を抑えます。

JpRxOnlyでは、走査中の高速候補確認、RSSI履歴表示、走査進捗表示、範囲走査時のサブオーディブル検出を有効にしています。高速確認は無線機側のスキャン設定で停止でき、通常の全候補評価へ戻せます。RSSI履歴と進捗表示は表示専用で、周波数、メモリー、校正データを変更しません。

AM／USBではBK4819のCSS検出器を使用できないため、F+STARによるCSSスキャン起動を拒否し、短いエラー音だけを返します。FM受信やFM放送スキャンの操作には影響しません。

### 3.10 FM受信時のゲイン制御

RXExt有効、通常のアナログFM受信、非スキャン時だけ、RSSIと受信ゲインの変化を10 ms周期で監視します。RSSIが-58 dBm以上になった場合は、ドライバの固定ゲイン設定を最小側へ切り替え、-78 dBm以下まで戻った時点で自動ゲイン制御へ復帰します。急なレベル変化には中間の固定ゲインを短時間適用し、音声のポンピングを抑えます。

FM放送モード、AM／USB、スキャン中、RXExt無効時はこの処理を行いません。これらの状態のAGCは、既存の無線機再設定処理に任せます。設定値やcalibration領域への書き込みはありません。

### 3.11 スケルチ自動校正の外れ値抑制

自動スケルチ校正は8回のRSSI・ノイズ・グリッチ測定から各項目の最大値と最小値を1回ずつ除外し、残る6回の平均で既存の開閉ヒステリシスを計算します。短いクリックや一時的なノイズバーストが、以後のスケルチ基準へそのまま残ることを抑える設計です。値は現在のVFO設定へ反映するだけで、校正テーブルは変更しません。

### 3.12 受信音声レベル履歴

JpRxOnlyでは、BK4829の音声出力レベルレジスタを20 ms周期で読み、43本の履歴バーとして表示します。これは音声サンプル列を使うFFTではなく、無線チップが提供する振幅エンベロープの履歴です。RXExt有効、通常の受信、非スキャン時に表示し、受信開始時は履歴と床値をリセットします。従来の送信側スコープ表示も維持します。

### 3.13 スキャンワッチ同時

RXExt有効かつ`TDR=DWR`のとき、メモリーチャンネル走査の次候補へ、受信側とは反対のVFOに表示されている有効なメモリーチャンネルを挿入します。これにより、走査対象とワッチ対象を同じ走査サイクルで確認できます。周波数モードのVFOは対象にせず、走査停止時の範囲復元を曖昧にしないようにしています。新しいEEPROM項目は追加していません。

### 3.14 メニュー簡易ヘルプ

受信専用版で意味を確認しにくい項目の下端へ、短い英数字の説明を表示します。SQLは`AUTO=measure noise`、帯域幅は`W20 N12 N-6`、`LIST CH`はスキャンリストへの所属、CTCSSは通常／逆の選択を示します。ヘルプ表示の前に下端の残り領域を消去し、15文字幅のウィンドウで長い説明を横スクロールするため、既存の画面要素や右端の描画と重なりません。表示は補助文だけであり、選択値や保存形式は変更しません。

### 3.15 起動画面・画像＋メッセージ・送信拒否表示・逆トーン

`POWER_ON_DISPLAY_MODE_ALL`で起動メッセージが空の場合は、受信専用版の既定表示として大フォントの`受信専用`と`JP RX-ONLY`を表示します。EEPROMから読む起動文は終端を検査し、未初期化値`0xFF`が残っていても画面外へ読み進めません。送信に相当する操作はビープだけで終わらせず、画面へ`TX DISABLE`を一時表示します。

ロゴ表示には`LOGO+MSG`を追加し、外部から読み込んだ画像を表示した上で、固定の`JP RX-ONLY`メッセージを重ねます。これは画像をOCRする機能ではなく、画像と版の用途を同時に確認するための表示モードです。

CTCSSメニューは、通常トーンの一覧の後ろに同じ周波数の逆トーンを配置します。逆トーンは受信側のCTCSS lost状態を採用し、通常トーンと一致条件を反転します。DCSとは別のコード種別として保存するため、既存のデジタルコードや校正データを変更しません。

## 4. 永続データと校正領域

### 4.1 K1の外部フラッシュ

下表は`PY25Q16_*`へ直接渡す物理アドレスです。EEPROM互換層で使う論理アドレスと混同しないでください。

| 物理領域 | 用途 | 形式 |
| --- | --- | --- |
| `0x00B000` | グローバル状態 | 8 bytes |
| `0x00B100` | チャンネルバンク | 1 byte / channel |
| `0x00B500` | 旧WIDE+互換メタデータ | 1 bit / channel |

グローバル8 bytesの配置は次のとおりです。

| byte | 内容 |
| ---: | --- |
| 0–1 | magic `RX` (`0x52, 0x58`) |
| 2 | format version。1を読み取り可能、保存は2 |
| 3 | flags: bit0=SINGLE、bit1=AUTO SQL、bit2=RXExt enabled |
| 4 | 選択バンク。0=ALL、1–8=バンク |
| 5 | 予約、現在は0 |
| 6–7 | byte 0–5へCRC16-CCITT、little-endian格納 |

未初期化・CRC不一致・範囲外のバンクは安全な既定値へ戻します。既定値はRXExt有効、全バンク、Wです。設定変更はdirtyフラグを経由して保存します。帯域幅の3段階は標準チャンネル記録のbyte 7へ保存します。

一方、EEPROM互換層の論理calibration窓`0xB000–0xB1FF`は外部フラッシュ物理`0x010000–0x0101FF`へ対応付けられます。これは上表の受信拡張領域とは別用途です。

### 4.2 CHIRPの境界

`tools/chirp/wrx_jp.py`はK1／K5 V3の機種プロファイルを使用し、通常の読み書き対象をメモリー・設定領域に限定します。calibration領域はアップロードのホワイトリストへ含めません。ただし、UARTの低レベルコマンドや外部保守ツールまで同じ拒否条件を保証するものではありません。書き込み前に個体の全イメージとcalibrationを保存してください。詳しい境界は[CHIRP技術ガイド](../tools/chirp/README.ja.md)を正とします。

## 5. 日本語表示とフォント

### 5.1 現行エンコーディング

メニュー文字列はUTF-8ではなく、ファームウェア内の1 byteコードです。K1では`0x80–0xFF`を拡張範囲として、`App/japanese_font.c`の大文字・小文字テーブルを参照します。大文字は1 glyph 14 bytes（7列×2ページ）、小文字は6 bytesの形式です。`App/ui/helper.c`は大文字日本語だけ表示基線を1 pixel下げ、ASCIIと欧文のベースラインに合わせています。

K1の大きい長音「ー」は拡張コード`0xE0`です。現在の表示変換で確実に水平線になるよう、ASCIIハイフンと同じ見え方を基準に glyph を補正しています。これはフォントファミリーの交換ではなく、既存テーブルの表示互換性を直す変更です。実機LCDでの視認性は別途確認が必要です。

既存atlasを再生成して空きスロットを確認したうえで、起動画面の「受信専用」に必要な大フォント`0x98=専`、`0x99=用`だけをプロジェクト作成字形として追加しています。小フォントの空き領域は再利用せず、次の追加候補は`0x9A`–`0xA0`です。割り当ての根拠と元バイト列は[FONT_BITMAP_ANNOTATIONS.ja.md](FONT_BITMAP_ANNOTATIONS.ja.md)およびatlas inventoryで管理します。

### 5.2 フォント候補の評価

| 候補 | ライセンス / 形式 | 採否 |
| --- | --- | --- |
| 現行Rainy由来データ | 本プロジェクトの既存帰属ではApache-2.0として扱う。7×14／小文字形式へ変換済み | 採用継続 |
| [M+ Fonts](https://mplusfonts.github.io/) | SIL Open Font License。小型表示向け系列もあるが、現行のbitmap配列への変換が必要 | 今回は不採用 |

## 6. 検証と既知の未検証範囲

ホスト側の正規確認は次のコマンドです。

```powershell
cmake --preset JpRxOnly
cmake --build --preset JpRxOnly -j2
python -m unittest discover -s tests -p "test_*.py" -v
```

主な回帰テストは`test_rx_jp_k1.py`、`test_receive_only_policy.py`、`test_rx_feature_state.py`、`test_receive_band_presets.py`、`test_receive_scan_skip.py`、`test_chirp_wrx_jp.py`、`test_rx_ui_and_reverse_tone.py`です。これらはソース定義、設定形式、境界条件、CHIRPの読み書き対象を検査しますが、RF性能やLCDの見え方を検査するものではありません。

実機では、対象個体のバックアップ後に表示版、PTTモニター、`TX DISABLE`表示、起動メッセージ、`LOGO+MSG`、ヘルプのスクロール、通常／逆CTCSS、FM 76.1–94.9 MHzの局、76.0／95.0 MHz端点の扱い、W／N／N-、RXExt、プリセット、バンク、スキャンスキップ、電源再投入後の設定復元を確認してください。特に大きい「ー」、日本語と欧文の基線、K1／K5 V3の帯域幅設定、CHIRPの読み取り後の校正データ不変性は、静的テストだけでは保証されません。

## 用語

- **RXExt**: 追加受信機能をまとめて切り替える永続設定。
- **W / N / N-**: K1／K5 V3の通常受信20／12.5／6.25 kHz設定。BK4829でW+を分離できないため、W+はこのプロファイルから除外。
- **bank**: メモリースキャンの論理グループ。0は全バンク。
- **calibration**: 個体ごとの校正データ。通常の利用者設定・CHIRPメモリーとは別に保護する。
- **logical / physical address**: EEPROM互換APIが扱う論理アドレスと、外部フラッシュへ直接渡す物理アドレス。
