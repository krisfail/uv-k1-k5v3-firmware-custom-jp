# wrx-jpの機能：技術詳細（UV-K1／UV-K5 V3）

`JpRxOnly`（`wrx-jp`）は，PY32F071搭載のUV-K1／UV-K5 V3向け受信専用ファームウェアです．操作手順は[README.ja.md](../README.ja.md)，日常操作の早見表は[CHEATSHEET.ja.md](../CHEATSHEET.ja.md)を参照してください．

## 1. ビルド入口と基本仕様

ビルドは`CMakePresets.json`の`JpRxOnly`を使用します．ルートCMakeが`ENABLE_RX_ONLY`を強制し，送信系の機能変数をOFFにします．主要な定義は次のとおりです．

| 定義 | 役割 |
| --- | --- |
| `ENABLE_RX_ONLY` | 送信経路・送信系UIを無効化し，PTTをモニター操作にする |
| CMake RX-only boundary | AirCopy，VOX，アラーム，送信トーン，送信タイマー，RFログなどの送信系モジュールを登録しない |
| `ENABLE_JAPANESE` | 日本語メニュー・カテゴリと外部チャンネル名フォントを有効化する。外部フォント未書込み時はメニューのASCIIフォールバックを使う |
| `ENABLE_RX_AGC_GUARD` | 通常のFM受信時の急激なAGC変化を抑える |
| `ENABLE_FMRADIO` | FM放送機能を有効化する |
| `TARGET=wrx-jp` | 生成物を上流版と区別する |
| `EDITION_STRING=JP-RX-Only` | 無線機上の版の用途を明示する |

K1とK5 V3は同じPY32プロファイルです．旧UV-K5（DP32G030）は異なるEEPROMマップとドライバ仕様を使用します．

`RXExt`は追加受信機能をまとめて切り替える設定です．OFFにすると，プリセット，SINGLE受信，メモリーバンクの絞り込み，自動スケルチ，AGCガード，一時スキップが停止します．受信専用制約，PTTモニター，外部チャンネル名表示，通常受信の帯域幅設定，FM放送の76.0–95.0 MHz制限は`RXExt`では解除されません．

## 2. 受信専用ポリシー

- `ACTION_Ptt()`は送信処理へ進まず，PTTをモニター操作として扱います．
- 送信系のメニュー，VOX，DTMF calling，送信トーンなどは`JpRxOnly`の定義でビルドされません．
- DUAL WATCHやCROSS BANDなど，送信経路を伴う状態から追加受信機能を起動しないよう，プリセット側にも拒否条件があります．
- `JpRxOnly`は国内向け受信専用版です．送信可能な構成は含みません．

## 3. 追加受信機能

### 3.1 受信モード

受信モードは`MAIN ONLY`，`DUAL RX`，`SINGLE`です．`SINGLE`は`RXExt`の有効時だけ選択でき，VFO切替を抑制します．状態はグローバル設定に保存されます．

### 3.2 通常受信の帯域幅

`W/N`で通常受信の帯域幅を切り替えます．選択値は標準チャンネル記録へ保存し，旧形式は互換処理で読み込みます．保存領域の詳細は「4.1 K1の外部フラッシュ」にまとめます．

### 3.3 自動スケルチ

自動スケルチは受信開始時などにRSSI，noise，glitchを8回，2 ms間隔でサンプリングします．平均値から次の6閾値を作り，通常の`BK4819_SetupSquelch()`へ渡します．

```text
open RSSI   = RSSI + 8       close RSSI   = RSSI + 4
open noise  = max(noise - 8, 0)
close noise = max(noise - 4, 0)
close glitch = glitch + 4     open glitch  = glitch + 8
```

各値は8 bit範囲へクランプします．自動スケルチの要求は一度消費すると再利用されず，`RXExt`または自動スケルチがOFFなら適用しません．

### 3.4 AGCガード

`ENABLE_RX_AGC_GUARD`時，`RXExt`有効，通常のFM受信，スキャン停止中，FM放送モード外だけで動作します．周波数ごとに前回サンプルを保持し，RSSI差が12以上または受信ゲイン差が8以上になった場合にAGCを一時停止します．停止保持はスケジューラ30回で，満了時にAGCを再有効化します．AMやFM放送の設定をこの処理が上書きしないよう，他の無線再構成経路を優先します．

### 3.5 メモリーバンク

チャンネルにはバンク番号0～8を持たせます．選択バンクが0（ALL）のときは全チャンネル，1～8のときは一致するチャンネルだけをメモリースキャン候補にします．保存形式は標準の周波数・名前・校正データと分離しています．

### 3.6 一時スキップ

スキャン中の一時スキップは周波数をRAM上の最大16件のリストへ追加します．同一周波数は重複登録せず，満杯の場合は追加しません．周波数スキャンとメモリースキャンの両方で候補を確認し，候補をすべて飛ばした場合も無限ループにならないよう試行回数に上限を設けています．電源再投入やスキャン範囲のリセットで消えます．

### 3.7 受信バンドプリセット

### 3.8 FM放送と日本向け仕様の照合

日本のFM放送局周波数の目安は76.1–94.9 MHzです．総務省系NICTの資料でも，臨時災害放送局用FM機器の送信可能周波数を76.1–94.9 MHz，電波型式をF3E/F8E（モノラル／ステレオ）として示しています（[NICT公式資料](https://www2.nict.go.jp/resil/book/2024/46132-book/pageindices/index87.html)）．

構成は次のとおりです．

| 項目 | 実装 | 説明 |
| --- | --- | --- |
| RFハードウェア | BK1080の76–108 MHzモード | 日本向け範囲を包含するため妥当 |
| UI・設定・CHIRP範囲 | 76.0–95.0 MHz，0.1 MHz単位 | 局範囲の外側に100 kHzずつ余裕がある |
| 周波数刻み | 内部単位で1，すなわち100 kHz．`FM_Space`の選択肢は無効化 | 日本の100 kHz級の局間隔に適合 |
| ステレオ／FM復調 | BK1080のFM放送モードへ委譲 | ソース上でモノラル／ステレオを個別選択する機能はない |

76.1–94.9 MHzの日本の局を受信できます．UI・自動選局・CHIRPでは76.0 MHzと95.0 MHzも入力・スキャン端点として許可し，BK1080の内部ハードウェア範囲は76–108 MHzです．

### 3.9 スキャン候補の受信確認と表示

周波数スキャンがVHF帯の第2高調波に相当する候補を検出した場合，候補周波数だけで判定を確定しません．候補の半分の周波数へ一度同調してRSSIを読み，その後候補周波数へ戻して再度RSSIを読みます．基礎周波数のRSSIが十分強い場合は，CSSスキャンへ渡す周波数を基礎周波数へ置き換えます．これにより，VHF帯で高調波を実信号として扱う誤停止を抑えます．

JpRxOnlyでは，走査中の高速候補確認，RSSI履歴表示，走査進捗表示，範囲走査時のサブオーディブル検出を有効にしています．高速確認は無線機側のスキャン設定で停止でき，通常の全候補評価へ戻せます．RSSI履歴と進捗表示は表示専用で，周波数，メモリー，校正データを変更しません．

AM／USBではBK4819のCSS検出器を使用できないため，F+STARによるCSSスキャン起動を拒否し，`FM ONLY`を表示して短いエラー音を返します．FM受信やFM放送スキャンの操作には影響しません．

### 3.10 FM受信時のゲイン制御

RXExt有効，通常のアナログFM受信，非スキャン時だけ，RSSIと受信ゲインの変化を10 ms周期で監視します．RSSIが-58 dBm以上になった場合は，ドライバの固定ゲイン設定を最小側へ切り替え，-78 dBm以下まで戻った時点で自動ゲイン制御へ復帰します．急なレベル変化には中間の固定ゲインを短時間適用し，音声レベルの揺れ（ポンピング）を抑えます．

FM放送モード，AM／USB，スキャン中，RXExt無効時はこの処理を行いません．これらの状態では，既存の無線機再設定処理にAGCを任せます．設定値やcalibration領域への書き込みはありません．

### 3.11 スケルチ自動校正の外れ値抑制

自動スケルチ校正は8回のRSSI・ノイズ・グリッチ測定から各項目の最大値と最小値を1回ずつ除外し，残る6回の平均で既存の開閉ヒステリシスを計算します．短いクリックや一時的なノイズバーストが，以後のスケルチ基準へそのまま残ることを抑える設計です．値は現在のVFO設定へ反映するだけで，校正テーブルは変更しません．

### 3.12 受信音声レベル履歴

JpRxOnlyでは，BK4829の音声出力レベルレジスタを20 ms周期で読み，43本の履歴バーとして表示します．音声サンプル列は使わず，無線チップが提供する振幅エンベロープを履歴として表示します．RXExt有効，通常の受信，非スキャン時に表示し，受信開始時は履歴と床値をリセットします．従来の送信側スコープ表示も維持します．

### 3.13 スキャンワッチ同時

RXExt有効かつ`TDR=DWR`のとき，メモリーチャンネル走査の次候補へ，受信側と反対のVFOに表示された有効なメモリーチャンネルを挿入します．これにより，走査対象とワッチ対象を同じ走査サイクルで確認できます．周波数モードのVFOは対象にせず，走査停止後の範囲を確実に復元します．新しいEEPROM項目は追加していません．

### 3.14 メニュー簡易ヘルプ

受信専用版で意味を確認しにくい項目の下端へ，短い日本語の説明を表示します．外部フォントが利用できない場合は英数字の説明へ戻ります．SQL，帯域幅，`LIST CH`，CTCSSなどの設定内容を補足します．ヘルプ表示の前に下端の右側だけを消去し，長い英数字の説明を11文字幅のウィンドウで横スクロールします．左下のノンブル（`02/47`など）と中央の仕切りは消去・描画の対象外とし，補助説明や右端の描画と重ならないようにします．表示は補助文だけであり，選択値や保存形式は変更しません．

カテゴリ画面はDondji風のランチャーとして構成し，現在カテゴリの大きな線画アイコン，カテゴリ名，カテゴリ内の項目数，カテゴリ位置を表示します。カテゴリ名はアイコン直下の小字ページ，件数とカテゴリ位置は最下段の別ページへ置き，16×16字形と件数表示が重ならないようにしています。分類はF4HWN側のカテゴリ定義をそのまま使い，カテゴリ内の項目順，メニューID，設定値，RX-only境界は変更しません。K1の左右キーでカテゴリを切り替え，数字キー1〜9でも先頭から9カテゴリを直接選べます。`MENU`でカテゴリ内の項目一覧へ入り，`EXIT`でランチャーへ戻ります。既存の`UP/DOWN`によるカテゴリ移動も互換操作として残します。カテゴリ画面の配置は[LCDエミュレータ](LCD_EMULATOR.ja.md)で確認できます。

### 3.15 起動画面・画像＋メッセージ・送信拒否表示・逆トーン

受信専用版では`MESSAGE`と`ALL`のどちらを選んでも，EEPROMに残った上流版の起動文を使わず，固定ASCIIの`RX ONLY`と`JP RX-ONLY`を表示します．短い固定文字列を使うため，固定長EEPROMの余白や古い文字列が画面幅を超えて乱れることも避けられます．`VOLTAGE`は従来どおり電圧表示です．EEPROMから読む起動文は終端を検査し，未初期化値`0xFF`が残っていても画面外まで読み出しません．受信専用ビルドでは送信出力の`LOW1`〜`HIGH`表示を描画せず，予期しないTX要求が最終ゲートへ到達した場合だけ，ビープと`RX ONLY`を表示します（内部状態名は`TX DISABLE`）．受信機能の条件不成立も，`RXExt OFF`，`VFO ONLY`，`SCAN ACTIVE`など短い理由を画面へ出してからビープを返します．

ロゴ表示の`LOGO+MSG`は，外部から読み込んだ画像を先に表示し，その後に固定の`JP RX-ONLY`メッセージへ切り替えます．`LOGO+ALL`は，画像の後に`ALL`相当の受信専用画面（`RX ONLY`，`JP RX-ONLY`，版情報）へ切り替えます．画像と文字列を同一フレームへ重ねないため，ロゴの内容や文字列が互いに隠れません．

CTCSSメニューは，通常トーンの一覧の後ろに同じ周波数の逆トーンを配置します．逆トーンは受信側のCTCSS lost状態を採用し，通常トーンと一致条件を反転します．DCSとは別のコード種別として保存するため，既存のデジタルコードや校正データを変更しません．

### 3.16 受信音声プロファイル

K1／K5 V3の`JpRxOnly`では，フラッシュ容量に余裕があるため，受信音声プロファイルを有効にしています．プロファイルを切り替えても，変更するのは音声出力側の設定だけです．周波数，帯域幅，チャンネル，送信経路，calibration領域には触れません．音声レベル履歴や音声スコープと同時に使っても，表示用の履歴を保存領域へ書き込みません．

K1／K5 V3では`ENABLE_FEAT_F4HWN_AUDIO=ON`です．旧UV-K5ではこの機能を無効にします．機種ごとのCMake／Makefile境界は共有しません．

### 3.17 主画面チャンネル名の表示モード

16×16の全角・ASCII混在表示では、全角字形を16行のまま使用し、内蔵大字形（14行）のASCIIだけを1px下げて中央揃えにします。全角字形が上下1pxずつ広がる配置です。14×14は16pxの名前枠内で1px下げ、8×8は名前だけを表示する場合に16px枠の中央へ配置します。周波数を直下に表示するデュアルVFOでは、8×8名前を上段に収め、名前中の和文とASCIIを同じ8pxセル基準へ置きます。周波数は1px下げて名前との間に1pxの空白を確保し、モード・コード・帯域幅などのステータス行も1px下げて周波数との間に1pxの空白を確保します。下方突出を持つASCII字形の形状は変更しません。

14×14表示は設定値`3`で選択します。外部Flashに保存した専用14px bitmapをそのまま描画し、16×16の2値bitmapを実機上で縮小しません。14px BDFにない記号は生成時にIzumi 16から補完します。デュアルVFOでは、従来の16×16選択と同じく美咲8×8表示へ自動的に切り替えます。

主操作画面のチャンネル名だけを，メニューの「主画面チャンネル名」で切り替えます。16×16日本語は外部Izumi bitmapを使い，14×14は専用14px bitmapを使います。8×8美咲は美咲ゴシックのネイティブ8×8 bitmapを使い，16×16字形を実機上で縮小しません。14×14は内蔵大字形（7×14）と高さを揃えたい場合に使います。ASCIIを選んだ場合は外部字形を使わず，チャンネルリストの`ascii_name`を表示し，別名がなければ`CH-xxxx`へ戻します。単一VFOのASCII名は収まる限り大字形，デュアルVFOのASCII名は小字形です。デュアルVFOでは，16×16または14×14を選んだ場合も4ページの表示領域に合わせて日本語名を美咲8×8へ切り替え，周波数も小字形で表示します。ASCIIは全モードで既存のF4HWN系内蔵フォントを使います。受信ステータス行の右端はチャンネルリストバッジ用に予約し，ステップ値は末尾の不要な0を省略して`SQL`表示との接触を避けます。固定UIのメニュー・カテゴリは日本語を主表示とし，16×16で48pxの項目欄に収まらないラベルだけ美咲8×8へ切り替えます。

設定値はK1/K5 V3設定領域`0xA15B`の下位2 bitへ保存します。既存の同byteの他bitは保持します。`0`は16×16，`1`は8×8美咲，`2`はASCII，`3`は専用14×14で，範囲外の値は16×16へ戻します。チャンネルリストの列と保存領域は[チャンネルリスト形式](CHANNEL_LIST_FORMAT.ja.md)に分けて記載します。

### 3.18 上流非送信機能の取り込み

上流v5.9.0の変更のうち，受信運用またはUIに関係する機能は`JpRxOnly`に含まれます．機能とRX-only境界は次のとおりです．

| 機能 | 実装 | RX専用境界 |
| --- | --- | --- |
| FMスキャン中の受信割り込み抑制 | `CheckForIncoming()`と`HandleIncoming()`でFMスキャン状態を確認し，通常チャンネルの受信開始を抑止 | FM放送スキャンの状態遷移と表示は維持する |
| メモリースキャン名表示中の再開保留 | `UI_MAIN_ShouldHoldScanResume()`がチャンネル名の表示期限中だけ再開を遅らせる | 周波数スキャンや名前を表示しない走査では保留しない |
| メニューカテゴリ | F4HWNの分類を使うDondji風ランチャー，線画アイコン，`ALL`フォールバックを追加し，空のカテゴリは表示しない | RX-onlyで存在しない送信項目はカテゴリ配列から除外する |
| サイドキー操作選択 | `F`＋サイドキー長押しで候補を選び，`M`で確定 | `POWER`，`PTT`，その他の送信系アクションは候補表示と実行の両方で拒否する |
| 2桁表示 | カテゴリ番号とカテゴリ内項目数を`%02u`で表示 | 表示形式だけの変更で，メニューIDと保存形式は変更しない |

カテゴリ名，メニュー項目名，設定値，サイドキー操作名の日本語は`App/ui/menu_text_ja.h`へ分離しています．外部フォントが利用できない場合は，項目ごとに用意したASCII表記へ戻ります．通常のメニュー項目の順序・ID・EEPROM配置は変わりません．

Fox Hunt／Beacon，BYP／BYP+，送信タイマー，送信電力・送信トーンを伴う機能は，受信専用ポリシーと衝突するため`JpRxOnly`では無効です．

## 4. 永続データと校正領域

### 4.1 K1の外部フラッシュ

下表は`PY25Q16_*`へ直接渡す物理アドレスです．EEPROM互換層で使う論理アドレスと混同しないでください．

| 物理領域 | 用途 | 形式 |
| --- | --- | --- |
| `0x00B000` | グローバル状態 | 8 bytes |
| `0x00B100` | チャンネルバンク | 1 byte / channel |
| `0x00B500` | チャンネル拡張メタデータ | 1 bit / channel |
| `0x010000–0x010FFF` | calibration sector（予約・保護） | 論理`0xB000–0xB1FF`を含む4 KiB。日本語書込み対象外 |
| 0x020000 | 外部日本語bitmapフォント | 251208 bytes、Izumi 16＋専用14px bitmap＋美咲8×8 bitmap |
| 0x060000 | 日本語チャンネル名 | 1024 × 32 bytes、UTF-8 payloadは最大31 bytes |

グローバル領域（8 bytes）の配置は次のとおりです．

| byte | 内容 |
| ---: | --- |
| 0–1 | magic `RX` (`0x52, 0x58`) |
| 2 | format version．1を読み取り可能，保存は2 |
| 3 | flags: bit0=SINGLE，bit1=AUTO SQL，bit2=RXExt enabled |
| 4 | 選択バンク．0=ALL，1–8=バンク |
| 5 | 予約，現在は0 |
| 6–7 | byte 0–5へCRC16-CCITT，little-endian格納 |

未初期化・CRC不一致・範囲外のバンクは安全な既定値へ戻します．既定値はRXExt有効，全バンク，標準受信帯域です．設定変更はdirtyフラグを経由して保存します．帯域幅の選択値は標準チャンネル記録のbyte 7へ保存します．

EEPROM互換層の論理calibration窓`0xB000–0xB1FF`は，外部フラッシュ物理`0x010000–0x0101FF`へ対応付けられます．sector消去単位の巻き込みを防ぐため，物理`0x010000–0x010FFF`全体をcalibration保護範囲とします．これは上の表の受信拡張領域とは別の用途です．firmwareの日本語外部Flash allowlistとWebSerial host tool，Python host toolの範囲検査は，このsectorと重ならない範囲だけを許可します．

### 4.2 CHIRPの境界

通常の操作環境は`tools/webui/`のWebSerial host toolです．メモリー，設定，チャンネル一覧，日本語リソースを分け，変更byte・変更block・readback状態を表示します．ブラウザーを使えない場合や通信契約をデバッグする場合は，`tools/host/wrx_jp_host.py`のPython GUIを使用できます．このGUIは試作・デバッグ用で，日本語リソースのフォントと名前テーブルを個別に書き込めます．いずれのhost toolも，接続時にversion応答と日本語外部Flashコマンドを確認し，各ブロックのreadback一致まで最大3回再試行します．ブラウザー版の操作手順は[WebSerial host tool技術ガイド](WEB_SERIAL_HOST.ja.md)，Python GUIの操作手順は[Python host tool技術ガイド](../tools/host/README.ja.md)を参照してください．

`tools/chirp/wrx_jp.py`はK1／K5 V3の機種プロファイルを使用する移行用互換アダプタです．CHIRPへロードする配布物は，このソースにフォントとmanifestを内蔵して生成した`tools/chirp/wrx_jp_standalone.py`です．外部Flash用UARTコマンドは`JpRxOnly`ファームウェア側の機能であり，CHIRPモジュールをロードするだけでは純正ファームウェアへフォントや日本語名を書き込めません．calibration領域はWebSerial host tool，Python GUI，CHIRPの通常アップロードのホワイトリストへ含めません．ただし，UARTの低レベルコマンドや外部保守ツールまで同じ拒否条件を保証するものではありません．書き込み前に個体の全イメージとcalibrationを保存してください．詳細は[CHIRP互換アダプタ技術ガイド](../tools/chirp/README.ja.md)を参照してください．

## 5. 日本語表示とフォント

### 5.1 現行エンコーディングとフォント監査

外部16×16字形，専用14×14字形，美咲8×8字形は，同じUnicode索引を共有します。8×8は専用のネイティブbitmapを使うため，16×16からの実機上の縮小処理は行いません。14×14の記号補完だけは生成時にIzumi 16を使います。

固定UIのメニュー，カテゴリ，警告，操作選択は，日本語を主表示とし，画面領域と可読性に応じて日本語・ASCII略号・単位を使い分けます．外部フォント未書込み時にも操作に必要な情報を失わないよう，メニュー項目にはASCIIフォールバックを用意します．16×16欄に収まらない選択中の日本語項目は8×8で16px枠の中央へ置き，左ペインを反転して選択状態を示します．UTF-8のチャンネル名は固定UIと同じ外部フォント経路を利用します．

内蔵フォントは`App/font.c`のASCII大字形，小字形，数字字形，最小字形で構成します．通常大字形は1 glyph 14 bytes（7列×2ページ），小字形は6 bytesの固定形式です．点灯する上下範囲は字形ごとに異なるため，単一サイズの字形に一律の上下空白を仮定しません．異なるサイズを混在させる場合だけ，ASCIIを変えず，和文側を各bitmapの実測結果に基づいて配置します．

大字形と小字形は別配列で管理します．編集時は配列ごとの要素幅とASCIIコード範囲を確認し，配列の出現順だけで対応付けません．

small字形は情報量の多い長い日本語ラベルに使い，短いラベルは16×16で描画します．通常のメニュー・カテゴリ・操作選択から日本語を排除せず，幅に収まらない場合だけ美咲8×8へ切り替えます．外部フォントが使えない場合は項目ごとのASCIIフォールバックを表示します．純正ファームウェアからの外部フォントのアップロードはできません．

固定UIでは長音を含む語も，字形と表示幅を確認したうえで日本語として扱います．必要な場合は短い日本語，略号，単位を選びます．外部Izumiフォントのチャンネル名では，保存されたUnicodeコードポイントをそのまま検索します．

受信専用の起動画面と警告は`RX ONLY`／`JP RX-ONLY`を使用します．旧来の内部日本語大字形・小字形・起動画面専用字形はビルド対象から除外しています．

チャンネル名は，書込み済み外部16×16フォントへ変換でき，かつ欄内に収まる場合だけ外部fontを試行します．未書込み，未収録，幅超過，またはASCII表示モードでは保存済みASCII名へ戻し，空ならチャンネル番号を表示します．

外部フォントはIzumi 16から漢字，かな，記号を含む16×16字形を生成し，14×14には専用14px BDF，美咲8×8にはMisaki Gothic 8dot BDFの字形を格納します．14px BDFにない記号は生成時にIzumi 16から補完します．ASCIIは重複収録せず，既存のF4HWN系内蔵フォントと保存済みASCII名を使います．ASCIIと和文の混在時は，実インク間隔を計算し，1px未満の境界だけ和文側へ空きを追加します．`NAME+FREQ`では，単一VFOの16×16名と大字形周波数を別のページへ配置します．8×8名またはASCII名のデュアルVFOでは，名前，周波数，補助情報，RSSIをそれぞれのLCDページへ分離し，名前と周波数，周波数とステータスの間に1px以上の空白を保ちます．混在名の和文とASCIIは同じ8pxセル基準へ置き，下方突出を持つASCII字形の形状は変更しません．補助情報とRSSIの数値は6×8字形へ統一し，表示内容は実際の変調，コード，帯域幅，スケルチ状態を表します．生成形式，対象コードポイント，入力SHA-256，外部Flash配置は，font manifestと[外部日本語フォントREADME](fonts/README.ja.md)に記載しています．

現行フォントの出所と変換規則は[フォントの出所と変換](FONT_SOURCES.ja.md)に，生成済み資産の対応は[フォント割り当て台帳](FONT_BITMAP_ANNOTATIONS.ja.md)とmanifestに記録しています．既存部分の帰属はルートの[NOTICE](../NOTICE)にも記載しています．

## 6. 検証と既知の未検証範囲

ホスト側の正規確認は次のコマンドです．

```powershell
cmake --preset JpRxOnly
cmake --build --preset JpRxOnly -j2
python -m unittest discover -s tests -p "test_*.py" -v
```

主な回帰テストは`test_rx_jp_k1.py`，`test_rx_ui_and_reverse_tone.py`，`test_chirp_wrx_jp.py`，`test_host_tool.py`，`test_webui.py`，`test_lcd_emulator.py`，`test_generate_japanese_font.py`です．これらはソース定義，設定形式，host toolの通信境界，LCDフレーム変換，フォント生成を検査します．RF性能やLCDの見え方は検査しません．

実機では，対象個体をバックアップしてから，表示版，PTTモニター，`RX ONLY`表示，起動メッセージ，`LOGO+MSG`，通常／逆CTCSS，FM 76.1–94.9 MHzの局，76.0／95.0 MHz端点の扱い，受信帯域，RXExt，プリセット，バンク，スキャンスキップ，電源再投入後の設定復元を確認してください．特に大きい「ー」，日本語と欧文の基線，K1／K5 V3の帯域幅設定，CHIRPのフォント・名前テーブル転送，読み取り後も校正データが変わらないことは，静的テストだけでは保証できません．

## 用語

- **RXExt**: 追加受信機能をまとめて切り替える永続設定．
- **bank**: メモリースキャンの論理グループ．0は全バンク．
- **calibration**: 個体ごとの校正データ．通常の利用者設定・CHIRPメモリーとは別に保護する．
- **logical / physical address**: EEPROM互換APIが扱う論理アドレスと，外部フラッシュへ直接渡す物理アドレス．
- **AGC**: 受信信号の強さに応じて受信ゲインを調整する自動利得制御．
- **RSSI**: 受信信号強度の指標．スケルチや候補周波数の判定に使う．
- **CTCSS / DCS**: 受信音を開く条件に使うアナログ／デジタルの選択信号．
- **VFO**: 周波数を直接変更する操作領域．
- **EEPROM**: 電源を切っても設定を保持する不揮発性メモリー．
- **UART**: パソコンや保守ツールとシリアル通信するインターフェース．
- **CRC16-CCITT**: 保存データの破損を検出する16 bitの検査値．
