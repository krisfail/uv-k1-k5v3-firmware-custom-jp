# wrx-jpの新機能：技術詳細（UV-K1／UV-K5 V3）

この文書は，PY32F071搭載のUV-K1／UV-K5 V3向け`JpRxOnly`（`wrx-jp`）の技術資料です．実装者やレビュー担当者が，コードとデータの境界を確認するときに使います．利用者は，対象機種，書き込み前の注意，通常操作を[README.ja.md](../README.ja.md)で確認し，日常操作は[CHEATSHEET.ja.md](../CHEATSHEET.ja.md)を参照してください．

ここでは利用者向けの操作手順やAIエージェント向けの作業規則は扱いません．操作手順はREADME，作業規則は[AGENTS.md](../AGENTS.md)を正本とします．

## 1. 正規の実装入口と前提

正規ビルドの入口は`CMakePresets.json`の`JpRxOnly`だけです．ルートCMakeが`ENABLE_RX_ONLY`を強制し，送信系の機能変数をOFFにします．主要な定義は次のとおりです．

| 定義 | 役割 |
| --- | --- |
| `ENABLE_RX_ONLY` | 送信経路・送信系UIを無効化し，PTTをモニター操作にする |
| CMake RX-only boundary | AirCopy，VOX，アラーム，送信トーン，送信タイマー，RFログなどの送信系モジュールを登録しない |
| `ENABLE_JAPANESE` | 日本語メニューと拡張フォントを有効化する |
| `ENABLE_RX_AGC_GUARD` | 通常のFM受信時の急激なAGC変化を抑える |
| `ENABLE_FMRADIO` | FM放送機能を有効化する |
| `TARGET=wrx-jp` | 生成物を上流版と区別する |
| `EDITION_STRING=JP-RX-Only` | 無線機上の版の用途を明示する |

K1とK5 V3は同じPY32プロファイルとして実装しています．旧UV-K5（DP32G030）のEEPROMマップやドライバ仕様を，この文書のアドレスへ読み替えてはいけません．

`RXExt`は追加受信機能をまとめて切り替える設定です．OFFにすると，プリセット，SINGLE受信，メモリーバンクの絞り込み，自動スケルチ，AGCガード，一時スキップが停止します．受信専用制約，PTTモニター，日本語表示，3段階の通常受信帯域幅，FM放送の76.0–95.0 MHz制限は`RXExt`では解除されません．

## 2. 受信専用ポリシー

- `ACTION_Ptt()`は送信処理へ進まず，PTTをモニター操作として扱います．
- 送信系のメニュー，VOX，DTMF calling，送信トーンなどは`JpRxOnly`の定義でビルド対象から外しています．
- DUAL WATCHやCROSS BANDなど，送信経路を伴う状態から追加受信機能を起動しないよう，プリセット側にも拒否条件があります．
- この版は国内向け受信機です．送信可能版の作成・再有効化は，この機能仕様の対象外です．

## 3. 追加受信機能

### 3.1 受信モード

受信モードは`MAIN ONLY`，`DUAL RX`，`SINGLE`です．`SINGLE`は`RXExt`の有効時だけ選択でき，VFO切替を抑制します．状態はグローバル設定に保存されます．

### 3.2 通常受信の帯域幅

K1／K5 V3では，実効差のないW+をメニューから外し，次の3段階にします．

| 表示 | 目標帯域幅 | 内部モード |
| --- | ---: | --- |
| `W` | 20 kHz | `BANDWIDTH_WIDE` |
| `N` | 12.5 kHz | `BANDWIDTH_NARROW` |
| `N-` | 6.25 kHz | `BANDWIDTH_NARROWER` |

`ACTION_Wn()`は`W → N → N- → W`の順に切り替えます．周波数ステップは帯域幅とは独立しており，既存のステップ選択から6.25／12.5／20／25 kHzを個別に選べます．そのため，FM放送など別の刻みを使うプリセットも維持できます．

K1／K5 V3のBK4829では，REG43の`<5:4>=10`が25 kHz／20 kHzを共通のハードウェアモードとして定義しています．Wは`BK4819_REG_43=0x3028`，Nは`0x4048`，N-は`0x2058`です．W+を別表示・別状態として残してもRF設定が変わらないため，このプロファイルでは実装しません．

帯域幅モードは，RX-only構成で標準チャンネル記録のbyte 7へ`0x80 | mode`として保存します．既存のbyte 4（WIDE/NARROW一ビット）は互換用に保持し，markerがない旧チャンネルや旧WIDE+状態はWへ正規化します．校正領域や外部フラッシュのバンク領域は使いません．

### 3.3 自動スケルチ

自動スケルチは受信開始時などにRSSI，noise，glitchを8回，2 ms間隔でサンプリングします．平均値から次の6閾値を作り，通常の`BK4819_SetupSquelch()`へ渡します．

```text
open RSSI   = RSSI + 8       close RSSI   = RSSI + 4
open noise  = max(noise - 8, 0)
close noise = max(noise - 4, 0)
close glitch = glitch + 4     open glitch  = glitch + 8
```

各値は8 bit範囲へクランプします．自動スケルチの要求は一度消費すると再利用されず，`RXExt`または自動スケルチがOFFなら適用しません．

### 3.4 AGCガード

`ENABLE_RX_AGC_GUARD`時，`RXExt`有効，通常のFM受信，スキャン停止中，FM放送モード外だけで動作します．周波数ごとに前回サンプルを保持し，RSSI差が12以上または受信ゲイン差が8以上になった場合にAGCを一時停止します．停止保持はスケジューラ30回で，満了時にAGCを再有効化します．AMやFM放送の設定をこの処理が上書きしないよう，他の無線再構成経路を優先します．

### 3.5 メモリーバンク

チャンネルにはバンク番号0～8を持たせます．選択バンクが0（ALL）のときは全チャンネル，1～8のときは一致するチャンネルだけをメモリースキャン候補にします．保存形式は標準の周波数・名前・校正データと分離しています．

### 3.6 一時スキップ

スキャン中の一時スキップは周波数をRAM上の最大16件のリストへ追加します．同一周波数は重複登録せず，満杯の場合は追加しません．周波数スキャンとメモリースキャンの両方で候補を確認し，候補をすべて飛ばした場合も無限ループにならないよう試行回数に上限を設けています．電源再投入やスキャン範囲のリセットで消えます．

### 3.7 受信バンドプリセット

### 3.8 FM放送と日本向け仕様の照合

日本のFM放送局周波数の目安は76.1–94.9 MHzです．総務省系NICTの資料でも，臨時災害放送局用FM機器の送信可能周波数を76.1–94.9 MHz，電波型式をF3E/F8E（モノラル／ステレオ）として示しています（[NICT公式資料](https://www2.nict.go.jp/resil/book/2024/46132-book/pageindices/index87.html)）．

現行実装は次の構成です．

| 項目 | 現行実装 | 判定 |
| --- | --- | --- |
| RFハードウェア | BK1080の76–108 MHzモード | 日本向け範囲を包含するため妥当 |
| UI・設定・CHIRP範囲 | 76.0–95.0 MHz，0.1 MHz単位 | 局範囲の外側に100 kHzずつ余裕がある |
| 周波数刻み | 内部単位で1，すなわち100 kHz．`FM_Space`の選択肢は無効化 | 日本の100 kHz級の局間隔に適合 |
| ステレオ／FM復調 | BK1080のFM放送モードへ委譲 | ソース上でモノラル／ステレオを個別選択する機能はない |

76.1–94.9 MHzの日本の局を受信する範囲には概ね対応しています．ただし，現在は76.0 MHzと95.0 MHzも入力・スキャン端点として許可するため，仕様範囲とは厳密には一致しません．受信機のガード範囲としては問題ありませんが，厳密に合わせるなら，UI・自動選局・CHIRPの検証範囲を761–949（0.1 MHz単位）へ変更し，BK1080の内部ハードウェア範囲だけを760–950のまま保持する設計が候補です．今回は互換性を優先し，コードを変更していません．

### 3.9 スキャン候補の受信確認と表示

周波数スキャンがVHF帯の第2高調波に相当する候補を検出した場合，候補周波数だけで判定を確定しません．候補の半分の周波数へ一度同調してRSSIを読み，その後候補周波数へ戻して再度RSSIを読みます．基礎周波数のRSSIが十分強い場合は，CSSスキャンへ渡す周波数を基礎周波数へ置き換えます．これにより，VHF帯で高調波を実信号として扱う誤停止を抑えます．

JpRxOnlyでは，走査中の高速候補確認，RSSI履歴表示，走査進捗表示，範囲走査時のサブオーディブル検出を有効にしています．高速確認は無線機側のスキャン設定で停止でき，通常の全候補評価へ戻せます．RSSI履歴と進捗表示は表示専用で，周波数，メモリー，校正データを変更しません．

AM／USBではBK4819のCSS検出器を使用できないため，F+STARによるCSSスキャン起動を拒否し，`FM ONLY`を表示して短いエラー音を返します．FM受信やFM放送スキャンの操作には影響しません．

### 3.10 FM受信時のゲイン制御

RXExt有効，通常のアナログFM受信，非スキャン時だけ，RSSIと受信ゲインの変化を10 ms周期で監視します．RSSIが-58 dBm以上になった場合は，ドライバの固定ゲイン設定を最小側へ切り替え，-78 dBm以下まで戻った時点で自動ゲイン制御へ復帰します．急なレベル変化には中間の固定ゲインを短時間適用し，音声レベルの揺れ（ポンピング）を抑えます．

FM放送モード，AM／USB，スキャン中，RXExt無効時はこの処理を行いません．これらの状態では，既存の無線機再設定処理にAGCを任せます．設定値やcalibration領域への書き込みはありません．

### 3.11 スケルチ自動校正の外れ値抑制

自動スケルチ校正は8回のRSSI・ノイズ・グリッチ測定から各項目の最大値と最小値を1回ずつ除外し，残る6回の平均で既存の開閉ヒステリシスを計算します．短いクリックや一時的なノイズバーストが，以後のスケルチ基準へそのまま残ることを抑える設計です．値は現在のVFO設定へ反映するだけで，校正テーブルは変更しません．

### 3.12 受信音声レベル履歴

JpRxOnlyでは，BK4829の音声出力レベルレジスタを20 ms周期で読み，43本の履歴バーとして表示します．音声サンプル列は使わず，無線チップが提供する振幅エンベロープを履歴として表示します．RXExt有効，通常の受信，非スキャン時に表示し，受信開始時は履歴と床値をリセットします．従来の送信側スコープ表示も維持します．

### 3.13 スキャンワッチ同時

RXExt有効かつ`TDR=DWR`のとき，メモリーチャンネル走査の次候補へ，受信側と反対のVFOに表示された有効なメモリーチャンネルを挿入します．これにより，走査対象とワッチ対象を同じ走査サイクルで確認できます．周波数モードのVFOは対象にせず，走査停止後の範囲を確実に復元します．新しいEEPROM項目は追加していません．

### 3.14 メニュー簡易ヘルプ

受信専用版で意味を確認しにくい項目の下端へ，短い英数字の説明を表示します．SQLは`AUTO=measure noise`，帯域幅は`W20 N12 N-6`，`LIST CH`はスキャンリストへの所属，CTCSSは通常／逆の選択を示します．ヘルプ表示の前に下端の残り領域を消去し，15文字幅のウィンドウで長い説明を横スクロールするため，既存の画面要素や右端の描画と重なりません．表示は補助文だけであり，選択値や保存形式は変更しません．

### 3.15 起動画面・画像＋メッセージ・送信拒否表示・逆トーン

受信専用版では`MESSAGE`と`ALL`のどちらを選んでも，EEPROMに残った上流版の起動文を使わず，大フォントの`受信専用`と`JP RX-ONLY`を表示します．短い固定文字列を使うため，固定長EEPROMの余白や古い文字列が画面幅を超えて乱れることも避けられます．`VOLTAGE`は従来どおり電圧表示です．EEPROMから読む起動文は終端を検査し，未初期化値`0xFF`が残っていても画面外まで読み出しません．受信専用ビルドでは送信出力の`LOW1`〜`HIGH`表示を描画せず，予期しないTX要求が最終ゲートへ到達した場合だけ，ビープと`TX DISABLE`を表示します．受信機能の条件不成立も，`RXExt OFF`，`VFO ONLY`，`SCAN ACTIVE`など短い理由を画面へ出してからビープを返します．

ロゴ表示には`LOGO+MSG`を追加し，外部から読み込んだ画像を表示した上で，固定の`JP RX-ONLY`メッセージを重ねます．画像はOCRせず，画像と版の用途を同時に確認する表示モードです．

CTCSSメニューは，通常トーンの一覧の後ろに同じ周波数の逆トーンを配置します．逆トーンは受信側のCTCSS lost状態を採用し，通常トーンと一致条件を反転します．DCSとは別のコード種別として保存するため，既存のデジタルコードや校正データを変更しません．

### 3.16 受信音声プロファイル

K1／K5 V3の`JpRxOnly`では，フラッシュ容量に余裕があるため，受信音声プロファイルを有効にしています．プロファイルを切り替えても，変更するのは音声出力側の設定だけです．周波数，帯域幅，チャンネル，送信経路，calibration領域には触れません．音声レベル履歴や音声スコープと同時に使っても，表示用の履歴を保存領域へ書き込みません．

この機能は，K5の容量制約を理由に同じ構成へは持ち込みません．機種ごとのCMake／Makefile境界を混ぜず，K1／K5 V3では`ENABLE_FEAT_F4HWN_AUDIO=ON`，K5では受信専用監査表に従って無効にします．

## 4. 永続データと校正領域

### 4.1 K1の外部フラッシュ

下表は`PY25Q16_*`へ直接渡す物理アドレスです．EEPROM互換層で使う論理アドレスと混同しないでください．

| 物理領域 | 用途 | 形式 |
| --- | --- | --- |
| `0x00B000` | グローバル状態 | 8 bytes |
| `0x00B100` | チャンネルバンク | 1 byte / channel |
| `0x00B500` | 旧WIDE+互換メタデータ | 1 bit / channel |

グローバル領域（8 bytes）の配置は次のとおりです．

| byte | 内容 |
| ---: | --- |
| 0–1 | magic `RX` (`0x52, 0x58`) |
| 2 | format version．1を読み取り可能，保存は2 |
| 3 | flags: bit0=SINGLE，bit1=AUTO SQL，bit2=RXExt enabled |
| 4 | 選択バンク．0=ALL，1–8=バンク |
| 5 | 予約，現在は0 |
| 6–7 | byte 0–5へCRC16-CCITT，little-endian格納 |

未初期化・CRC不一致・範囲外のバンクは安全な既定値へ戻します．既定値はRXExt有効，全バンク，Wです．設定変更はdirtyフラグを経由して保存します．帯域幅の3段階は標準チャンネル記録のbyte 7へ保存します．

EEPROM互換層の論理calibration窓`0xB000–0xB1FF`は，外部フラッシュ物理`0x010000–0x0101FF`へ対応付けられます．これは上の表の受信拡張領域とは別の用途です．

### 4.2 CHIRPの境界

`tools/chirp/wrx_jp.py`はK1／K5 V3の機種プロファイルを使用し，通常の読み書き対象をメモリー・設定領域に限定します．calibration領域はアップロードのホワイトリストへ含めません．ただし，UARTの低レベルコマンドや外部保守ツールまで同じ拒否条件を保証するものではありません．書き込み前に個体の全イメージとcalibrationを保存してください．詳細な境界は[CHIRP技術ガイド](../tools/chirp/README.ja.md)を参照してください．

## 5. 日本語表示とフォント

### 5.1 現行エンコーディングとフォント監査

メニュー文字列はUTF-8ではなく，ファームウェア内の1 byteコードで表します．正規の対応表は[フォント割り当て台帳](FONT_BITMAP_ANNOTATIONS.ja.md)に置きます．`0x21–0x7E`は現在の実装どおりASCII，`0xA1–0xDF`はJIS X 0201半角カタカナ，その他の拡張範囲はプロジェクト固有のコードとして扱います．`0x80–0xA0`と`0xE0–0xFF`をJIS文字として自動解釈してはいけません．

K1では`0x80–0xFF`を`App/japanese_font.c`の大／小フォントテーブルで扱います．通常大字形は1 glyph 14 bytes（7列×2ページ），小字形は6 bytesの固定形式です．大字形は欧文・日本語とも同じ固定セルと描画APIを使いますが，点灯する上下範囲は字形ごとに異なります．上下の空白を固定規則にせず，実際のビットマップを正本にします．

rainy由来の基準大字形では，コードポイントと配列行の対応不整合が確認されています．実行時添字は`code - 0x21`であり，`0x9A–0xA5`と`0xB0`が空白になります．`0xA1`と注釈された行は実際には`0xA6`に対応し，`0xA6`と`0xDD`，`0xA7`と`0xB1`には完全一致するバイト列があります．small版には`0xA1–0xDF`の対応字形があるため，big／smallのコードポイント対応も崩れています．K1では大字形と小字形が別配列なので，K5の連続配列をバイト列として移植せず，コードポイントごとに再構成します．

現在のsmall字形はカタカナの視認性が低いため，通常の日本語メニューにはmedium層を設けます．数値・補助表示はsmall，メニュー・チャンネル名は8ドット程度の固定幅で縦10–12ドット程度のmedium，起動画面や警告は既存の10×16 largeを使い分ける構成を候補とします．K1はフラッシュに余裕があるため，mediumの字種をK5より広くできますが，表示幅，RAM使用量，LCD上の基線は実機で確認します．

ビットパック形式は将来の実装候補として評価できます．7×14画素では理論上13 bytes程度，12×12画素では18 bytesとなるため，常に容量が減るわけではありません．可変幅・可変高さを導入する場合は，`UI_CopyLargeGlyph`相当の描画，中央寄せ，クリッピング，文字列の幅計算，OLEDページ境界を一体で変更します．まずK1で試作し，表示品質と実サイズを測定してから共通化を判断します．

K1の大きい長音「ー」は拡張コード`0xE0`です．フォント配列でASCIIハイフンと同じ行へ固定し，描画時の個別変換は行いません．

既存atlasを再生成して空きスロットを確認したうえで，起動画面の「受信専用」に必要な`0x98=専`，`0x99=用`を独立再構成しました．`gFontJapaneseExtraLarge`は4スロットの疎な10×16表で，`UI_PrintStringJapaneseExtraLarge`から起動画面の登録コードだけを描画します．全コードポイント分を予約しないのは，フラッシュ容量と保守性を保つためです．

## 6. 検証と既知の未検証範囲

ホスト側の正規確認は次のコマンドです．

```powershell
cmake --preset JpRxOnly
cmake --build --preset JpRxOnly -j2
python -m unittest discover -s tests -p "test_*.py" -v
```

主な回帰テストは`test_rx_jp_k1.py`，`test_receive_only_policy.py`，`test_rx_feature_state.py`，`test_receive_band_presets.py`，`test_receive_scan_skip.py`，`test_chirp_wrx_jp.py`，`test_rx_ui_and_reverse_tone.py`です．これらはソース定義，設定形式，境界条件，CHIRPの読み書き対象を検査します．RF性能やLCDの見え方は検査しません．

実機では，対象個体をバックアップしてから，表示版，PTTモニター，`TX DISABLE`表示，起動メッセージ，`LOGO+MSG`，ヘルプのスクロール，通常／逆CTCSS，FM 76.1–94.9 MHzの局，76.0／95.0 MHz端点の扱い，W／N／N-，RXExt，プリセット，バンク，スキャンスキップ，電源再投入後の設定復元を確認してください．特に大きい「ー」，日本語と欧文の基線，K1／K5 V3の帯域幅設定，CHIRPの読み取り後も校正データが変わらないことは，静的テストだけでは保証できません．

## 用語

- **RXExt**: 追加受信機能をまとめて切り替える永続設定．
- **W / N / N-**: K1／K5 V3の通常受信20／12.5／6.25 kHz設定．BK4829でW+を分離できないため，W+はこのプロファイルから除外．
- **bank**: メモリースキャンの論理グループ．0は全バンク．
- **calibration**: 個体ごとの校正データ．通常の利用者設定・CHIRPメモリーとは別に保護する．
- **logical / physical address**: EEPROM互換APIが扱う論理アドレスと，外部フラッシュへ直接渡す物理アドレス．
- **AGC**: 受信信号の強さに応じて受信ゲインを調整する自動利得制御．
- **RSSI**: 受信信号強度の指標．スケルチや候補周波数の判定に使う．
- **CTCSS / DCS**: 受信音を開く条件に使うアナログ／デジタルの選択信号．
- **VFO**: 周波数を直接変更する操作領域．
- **EEPROM**: 電源を切っても設定を保持する不揮発性メモリー．
- **UART**: パソコンや保守ツールとシリアル通信するインターフェース．
- **CRC16-CCITT**: 保存データの破損を検出する16 bitの検査値．

実装の変更時は，対応するソース，ホストテスト，この資料，利用者向けREADMEの役割を分けて更新してください．未検証の結果を実機保証として記載しないでください．
