# rainy版との日本語大字形比較

この文書は，`rainy-knight/uv-k5-jp`の公開ソースを参照側として，現行の日本語大字形をソースレベルで比較した記録です．比較結果は字形の一致・差分を示すものであり，参照側のデータをファームウェアへ取り込んだことや，実機表示が同じであることを示すものではありません．

## 比較対象

- 参照側: `rainy-knight/uv-k5-jp`の`font.c`（Apache License 2.0）
- K5現行側: `font.c`
- K1現行側: `App/japanese_font.c`
- 対象: ソース中の14-byte，2ページ形式の大字形初期化子
- 範囲: `0x80`–`0xDF`

比較処理は，コードコメントまたは指定初期化子に付いたコード値を使って字形を対応付けます．小字形の6-byte配列や，単なる配列位置だけで対応付けられないデータは比較対象から除外します．参照データは読み取り専用で扱い，現行ソースを書き換えません．

## 現行ソースでの結果

| 対象 | 比較コード数 | 完全一致 | 差分あり | 参照のみ | 現行のみ |
| --- | ---: | ---: | ---: | ---: | ---: |
| K5 | 27 | 0 | 25 | 0 | 2 |
| K1 | 89 | 0 | 25 | 0 | 64 |

主なUI文字に対応する`0x80`–`0x97`の24字は，K5／K1とも24字すべてに差分があります．`0x98=専`と`0x99=用`は現行側に追加された字形です．K1では，さらに`0xA2`以降のK1向け追加字形が現行側だけにあります．`0xA1`は両方に存在しますが，主な日本語UI文字列の24字には含めていません．

この結果から，現行配列については「rainy版のバイト列をそのまま使用している」とは扱いません．由来の確認が必要な場合は，ソースの履歴，取り込みパッチ，変換手順を別途確認します．この比較ツールは，その履歴や著作権上の帰属を推定するものではありません．

## コードポイント対応に関する注意

参照側のアクティブな`gFontBig`は`!`（`0x21`）から始まり，実行時には`code - 0x21`で行を選びます．一方，`0xA1`と記されたコメント以降の行は，アクティブ配列上では5コード分後ろへずれています．そのため，コメントだけを使った比較結果を正しいコードポイント対応として扱うことはできません．

基準配列の実データでは`0x9A`–`0xA5`と`0xB0`が空白で，`0xA6`と`0xDD`，`0xA7`と`0xB1`が同一バイト列です．small版には`0xA1`–`0xDF`の対応字形があるため，今後の比較は[フォント割り当て台帳](FONT_BITMAP_ANNOTATIONS.ja.md)の正規コードポイント表へ再マッピングしてから行います．

## 比較ツールの使い方

参照リポジトリを任意の作業ディレクトリへ配置し，リポジトリのルートから実行します．パスは公開文書へ出力されません．

K5:

```powershell
python -X utf8 tools/compare_japanese_font.py `
  --reference-source <rainy-repo>\font.c `
  --current-source font.c `
  --out tmp\rainy-font-comparison-k5
```

K1:

```powershell
python -X utf8 tools/compare_japanese_font.py `
  --reference-source <rainy-repo>\font.c `
  --current-source App\japanese_font.c `
  --out tmp\rainy-font-comparison-k1
```

出力は次の3ファイルです．

- `font_diff.md`: コードごとの状態とバイト列
- `font_diff.json`: 機械処理用の差分データ
- `font_diff.svg`: 重ね合わせ表示（黒=双方，青=参照のみ，赤=現行のみ）

既存の`tools/font_editor.html`にある編集画面のリアルタイム差分は，この比較とは別の機能です．編集画面では，読み込み時の元データと現在の編集内容を比較します．
