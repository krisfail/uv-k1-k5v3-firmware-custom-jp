# wrx-jp CHIRP互換モジュール（移行用）

このモジュールは，専用Windows host toolへ移行した現在も互換・移行用として残す。正規の操作環境ではなく，新しい外部Flash機能を追加しない。

CHIRPの外部モジュール読み込み機能を使って`wrx-jp`対応ドライバを追加する。CHIRPへ読み込むファイルは、フォントを内蔵した配布用の`wrx_jp_standalone.py`である。

## CHIRPへ読み込む

1. `tools/chirp/wrx_jp_standalone.py`を取得する。
2. CHIRPを起動し、開発者向け機能が無効なら`Help → Enable Developer Functions`を一度実行する。
3. `File → Load Module`で`wrx_jp_standalone.py`を選ぶ。
4. モジュールを読み込んだ後に無線機のタブを開き、機種を選ぶ。

CHIRPの再起動後は外部モジュールを再度読み込む。開発用の`wrx_jp.py`はフォント資産をリポジトリから読むため、単独でコピーして使わない。フォントファイルを別途ドライバフォルダへ置く必要はない。

ただし、モジュールの読み込みだけではフォントも日本語名も無線機へ送れない。先に対象機種へこのリポジトリの`JpRxOnly`ファームウェアを書き込み、ファームウェアが起動している状態で使う必要がある。純正ファームウェアや別系統のファームウェアには、下記の外部Flash用UARTコマンドがないため対応しない。

機種の対応は次のとおりである。

| CHIRPで選ぶ機種 | ハードウェア | チャンネル数 | 日本語名 |
| --- | --- | ---: | --- |
| `UV-K1 / UV-K5 V3 (wrx-jp RX-only)` | PY32F071、外部Flash | 1024 | 対応 |

対象機種を確認し、無線機から全データを読み出してバックアップを保存する。

## フォントの扱い

Settings画面にフォント用の項目はない。また、FM放送の設定画面だけを開いてもフォントは送られない。現行アダプタでは、日本語フォントの転送をメモリー画面の通常`Upload to radio`へ暫定的に内包しているが、これは最終仕様ではない。正規host toolでは「日本語リソース書込み」として明示操作に分離する。日本語フォントは`wrx_jp_standalone.py`に圧縮して埋め込んでいる。

対象機種へ`JpRxOnly`ファームウェアを書き込んだ後、メモリー画面から通常のアップロードを実行すると、ドライバは次の順序で処理する。

1. 外部Flashの固定フォント領域`0x020000`を読み出し、内蔵フォントと照合する。
2. 一致しなければフォント全体を書き込み、128 byte単位でreadback確認する。
3. 日本語チャンネル名に変更があれば、外部Flashの名前テーブル`0x040000`へ書き込む。

フォントはIzumi 16を基にした固定セル字形で、manifest上の登録字形を使用する。CHIRP画面の名前文字数上限は10文字で、書き込み前にUTF-8で最大31 byte、表示幅はASCII 8 pixel、日本語字形16 pixelとして追加検査する。日本語名を空にした場合やASCII名へ戻した場合は、外部の名前レコードも消去する。

フォントの対応確認は通常メモリーの書き込みより先に行う。純正ファームウェアや外部Flashにアクセスできない状態では，通常メモリーも書き込まずに停止する。初回やフォント不一致時はチャンネル設定だけの書き込みより時間がかかる。書き込み中に無線機の電源や接続を切らない。

## Settings

`Settings`タブでは、F4HWN系の設定を受信専用境界に合わせて読み書きできる。

- 基本：スケルチ、チャンネル表示、バッテリーセーブ、デュアル受信、バックライト、スキャン再開、起動画面、バッテリー種別
- 表示・操作：輝度、コントラスト、表示反転、Sメーター、GUI、メニューロック、スリープタイマー、ビープ、キーロック、自動キーロック
- プログラマブルキー：サイドキー1／2、`M`長押し
- スキャン：標準リスト、有効・無効、優先チャンネル1／2、コールチャンネル
- F4HWN受信設定：FM／AM音声プロファイル、NFMナロー化
- 起動画面：ASCII 16文字を2行
- FM放送：現在周波数と48件のプリセット

送信電力、送信タイムアウト、送信トーン、DTMF送信、校正値、RX拡張状態はSettingsに出さない。受信専用のため、送信を開始する操作や送信設定をドライバから再導入していない。

## 配布用モジュールの再生成

ドライバ、フォントmanifest、またはフォントバイナリを変更した場合は、リポジトリのルートで次を実行する。

```text
python tools/build_chirp_module.py
```

生成物が最新かどうかだけを確認する場合は次を実行する。

```text
python tools/build_chirp_module.py --check
```

`wrx_jp.py`は開発用ソース、`wrx_jp_standalone.py`はCHIRPへ渡す生成済み配布物である。この2つを混同しない。

## 校正領域と検証範囲

CHIRPのアップロードは、通常のチャンネル・VFO・設定だけを対象とする。論理アドレス`0xB000–0xB1FF`の校正領域はアップロード対象に含めない。ただし、全データの読み出しには個体固有の校正値が含まれ得るため、読み出したバックアップは保存する。

これはCHIRPのアップロード経路に対する保護であり、UARTや保守用ツールなど別の低レベル書き込み経路を制限するものではない。

CHIRPの実機での読み書き、外部Flashへのフォント書き込み、表示結果は未検証である。ホスト側のテストとビルド成功は、実機動作の保証ではない。帰属・ライセンスは同じディレクトリの`NOTICE.md`と`LICENSE.txt`を参照する。
